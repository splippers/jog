1. Error Overview

The Permission denied error in FOG iPXE typically occurs during the boot chain when undionly.kpxe or ipxe.efi tries to fetch default.ipxe, kernel, or initrd files from the FOG server over HTTP/HTTPS.

Typical Screenshot Details

iPXE initialising devices...ok

iPXE 1.21.1+ (g1234) -- Open Source Network Boot Firmware
Features: DNS HTTP HTTPS iSCSI NFS TFTP VLAN SRP AoE EFI Menu

net0: 00:11:22:33:44:55 using undionly on PCI00:03.0 (open)
[Link:up, TX:0 TXE:0 RXE:0]
[DHCP (net0 00:11:22:33:44:55).......... ok]
net0: 192.168.1.100/255.255.255.0 gw 192.168.1.1
Next server: 192.168.1.10
Filename: default.ipxe

https://192.168.1.10/fog/service/ipxe/boot.php... Permission denied (http://ipxe.org/2c618c03)
Could not boot: Permission denied (http://ipxe.org/2c618c03)
No more network devices
Error Code 2c618c03: This iPXE error means the HTTP server returned 403 Forbidden or 401 Unauthorized. The client connected successfully but the server actively denied access to the requested file.

Common Symptoms

  • Clients get DHCP and contact FOG server but fail to load boot.php or bg.png
  • Works for undionly.kpxe but fails for ipxe.efi or vice versa
  • Error occurs only after FOG update, SSL cert change, or OS patching
  • Direct browser access to https://fog-server/fog/service/ipxe/boot.php shows 403/401

2. Quick Diagnosis Checklist

Run through this checklist before diving into specific fixes. This isolates the problem to server config, storage nodes, or SSL.

  • Can you access http(s)://fog-server/fog/management from a browser? If no, Apache is down or firewall blocked.
  • Does curl -k https://localhost/fog/service/ipxe/boot.php from FOG server return PHP output or 403/401?
  • Check Apache error log while triggering the boot: tail -f /var/log/apache2/error.log or /var/log/httpd/error_log
  • Is SELinux enforcing? Run getenforce. If "Enforcing", check audit log.
  • Did you recently change FOG web UI password or run installfog.sh? Storage node password may be out of sync.
  • Are you using HTTPS with self-signed certs? iPXE builds before 2019 don't trust them by default.
  • Check file permissions: ls -la /var/www/html/fog/service/ipxe/. Should be readable by Apache user.
  • If using multiple storage nodes, does the issue affect all nodes or just one?
iPXE Shell Test: Drop to iPXE shell during boot by pressing Ctrl+B when you see "Press Ctrl+B". Then run dhcp and imgfetch https://fog-ip/fog/service/ipxe/boot.php to see the exact HTTP error code.

3. Step-by-Step Fixes for Common Causes

3.1 Apache File Permissions

Most common cause. Apache user www-data or apache must read FOG web files and iPXE scripts.

Verify Apache User

# Ubuntu/Debian
ps aux | grep apache2 | grep -v grep
# RHEL/CentOS/Rocky
ps aux | grep httpd | grep -v grep

Note the user, typically www-data on Ubuntu or apache on RHEL.

Fix Ownership and Permissions

# Ubuntu/Debian
sudo chown -R www-data:www-data /var/www/html/fog
sudo find /var/www/html/fog -type d -exec chmod 755 {} \;
sudo find /var/www/html/fog -type f -exec chmod 644 {} \;

# RHEL/CentOS/Rocky
sudo chown -R apache:apache /var/www/html/fog
sudo find /var/www/html/fog -type d -exec chmod 755 {} \;
sudo find /var/www/html/fog -type f -exec chmod 644 {} \;

Restart Apache

# Ubuntu/Debian
sudo systemctl restart apache2

# RHEL/CentOS
sudo systemctl restart httpd

3.2 SELinux Context Violations

If SELinux is in Enforcing mode, it will block Apache from reading files with wrong context, returning 403.

Check SELinux Status

getenforce
sestatus

If it returns Enforcing, continue. If Disabled or Permissive, skip this section.

Check for Denials

sudo ausearch -m AVC -ts recent
# Or check log directly
sudo tail -50 /var/log/audit/audit.log | grep denied

Look for httpd denials on /var/www/html/fog.

Restore Correct Contexts

sudo restorecon -Rv /var/www/html/fog
sudo setsebool -P httpd_can_network_connect 1
sudo setsebool -P httpd_unified 1

If you store images outside /images, also run: sudo chcon -R -t httpd_sys_content_t /your/path

Test: Temporarily Set Permissive

For testing only. If setting permissive fixes boot, you have a confirmed SELinux issue. 
sudo setenforce 0
# Test PXE boot now
# Set back after testing
sudo setenforce 1

3.3 FOG Storage Node Password Mismatch

If you changed the FOG web UI password for user fogproject but didn't update Storage Node settings, iPXE scripts calling boot.php with credentials will fail.

Find Current Storage Password

sudo grep -i 'password' /opt/fog/.fogsettings

Note the fogstorageftp or password value.

Update in FOG Web UI

Login to FOG Management: Storage Management > [Your Node] > Management Username/Password

Set Username: fogproject and Password: value from .fogsettings

Also check: FOG Configuration > FOG Settings > TFTP Server > FOG_TFTP_FTP_PASSWORD

Sync to All Nodes

If you have multiple storage nodes, update each node's config with the same credentials. Mismatched nodes cause intermittent 403s.

3.4 SSL Certificate Issues

iPXE requires a valid cert chain. Self-signed certs or expired certs cause HTTPS boot.php requests to fail silently as "Permission denied".

iPXE Quirk: Undionly.kpxe built before Aug 2019 has no CA bundle. It cannot validate HTTPS at all unless you recompile iPXE with DOWNLOAD_PROTO_HTTPS and embed your CA.

Option A: Force HTTP for iPXE

Edit FOG Configuration > FOG Settings > Web Server > FOG_WEB_HOST and change https:// to http://. Also update FOG Configuration > FOG Settings > TFTP Server > FOG_PXE_BOOT_IMAGE

# In FOG_WEB_HOST field, use:
http://fog-server-ip

Option B: Trust Self-Signed Cert in iPXE

Rebuild iPXE with your CA cert. For most users, easier to use HTTP or Let's Encrypt.

cd /opt/fog/utils/FOGiPXE/
./buildipxe.sh

Option C: Use Valid Cert

Install Let's Encrypt via certbot, or import commercial cert into Apache. Ensure full chain is configured in Apache SSL config.

3.5 .htaccess / Apache Config Restrictions

Custom Apache rules or .htaccess in /fog/service/ipxe/ can block iPXE clients which don't send standard browser headers.

Check for .htaccess

ls -la /var/www/html/fog/service/ipxe/.htaccess
sudo cat /var/www/html/fog/service/ipxe/.htaccess

FOG default has no .htaccess here. If present, rename it: sudo mv .htaccess .htaccess.bak

Check Apache Directory Directives

# Ubuntu
sudo grep -r "Deny" /etc/apache2/
sudo nano /etc/apache2/sites-enabled/001-fog.conf

# RHEL
sudo grep -r "Deny" /etc/httpd/
sudo nano /etc/httpd/conf.d/fog.conf

Ensure <Directory /var/www/html/fog> has Require all granted not Require ip 127.0.0.1

Disable ModSecurity Temporarily

ModSecurity WAF can block iPXE clients. Check logs and whitelist if needed.

# Check if enabled
apache2ctl -M | grep security2
# Temporarily disable in fog.conf:
SecRuleEngine Off

4. Commands by OS Distro

Apache Service

sudo systemctl status apache2
sudo systemctl restart apache2
sudo systemctl reload apache2
sudo apache2ctl configtest

Check Logs

sudo tail -f /var/log/apache2/error.log
sudo tail -f /var/log/apache2/access.log
sudo tail -f /var/log/php*-fpm.log

Test Local HTTP

curl -v http://localhost/fog/service/ipxe/boot.php
wget -O- http://localhost/fog/service/ipxe/boot.php

FOG Re-run Installer

cd /path/to/fogproject/bin
sudo ./installfog.sh -y

Apache Service

sudo systemctl status httpd
sudo systemctl restart httpd
sudo systemctl reload httpd
sudo apachectl configtest

Check Logs

sudo tail -f /var/log/httpd/error_log
sudo tail -f /var/log/httpd/access_log
sudo tail -f /var/log/php-fpm/error.log

SELinux Audit

sudo ausearch -m AVC -ts recent
sudo sealert -a /var/log/audit/audit.log
sudo semanage fcontext -l | grep fog

Firewall Check

sudo firewall-cmd --list-all
sudo firewall-cmd --add-service=http --permanent
sudo firewall-cmd --add-service=https --permanent
sudo firewall-cmd --reload

5. How to Test in iPXE Shell

Drop into the iPXE command line to manually test URL access and see detailed HTTP responses.

Enter iPXE Shell

During FOG boot, when you see Press Ctrl+B for iPXE prompt, hit Ctrl+B quickly.

Initialize DHCP

iPXE> dhcp
iPXE> ifstat

Confirm you have an IP address on net0.

Test boot.php Access

iPXE> imgfetch http://192.168.1.10/fog/service/ipxe/boot.php
iPXE> imgstat

If you see HTTP 403 Forbidden or 401 Unauthorized, it's server-side. If Operation not supported, it's HTTPS cert issue.

Test with Credentials

If your FOG uses basic auth:

iPXE> imgfetch http://fogproject:password@192.168.1.10/fog/service/ipxe/boot.php

Chain Manually

iPXE> chain http://192.168.1.10/fog/service/ipxe/boot.php?mac=${net0/mac}

This mimics exactly what undionly.kpxe does. If it works here but not auto-boot, check DHCP option 67 filename.

6. Log File Locations

Check these logs in real-time while triggering a PXE boot to catch the exact error.

Component Ubuntu/Debian Path RHEL/CentOS Path What to Look For
Apache Error /var/log/apache2/error.log /var/log/httpd/error_log 403, 401, "Permission denied", "client denied by server configuration"
Apache Access /var/log/apache2/access.log /var/log/httpd/access_log HTTP status code for /fog/service/ipxe/boot.php
PHP-FPM /var/log/php8.1-fpm.log /var/log/php-fpm/error.log PHP fatal errors, permission issues loading scripts
SELinux Audit /var/log/audit/audit.log /var/log/audit/audit.log type=AVC msg=audit denials for httpd
FOG Multicast /opt/fog/log/multicast.log /opt/fog/log/multicast.log Not relevant for boot.php but useful for imaging
FOG Scheduler /opt/fog/log/fogscheduler.log /opt/fog/log/fogscheduler.log Task creation issues
Syslog /var/log/syslog /var/log/messages General system errors, OOM, network
Pro Tip: Open 2 terminals: tail -f /var/log/apache2/error.log in one, and watch the PXE boot in the other. The error will appear instantly when the client requests boot.php.

Quick One-Liner Log Watch

# Monitor all relevant logs at once
sudo tail -f /var/log/apache2/error.log /var/log/apache2/access.log /var/log/audit/audit.log
